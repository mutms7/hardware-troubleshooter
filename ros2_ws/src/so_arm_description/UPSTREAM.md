# Vendored SO-ARM101 description

Copied unchanged from https://github.com/MuammerBay/SO-ARM_ROS2_URDF at commit
`8a68d6e1106cbc570664a29f6d65af665cd30e72` (2025-05-27). Only `.git` was left out. The
repo's `.gitattributes` normalized line endings in the text files from CRLF to LF.
That repository declares a BSD license in `package.xml` and ships no separate LICENSE
file. It is derived from TheRobotStudio's SO-ARM100 project
(https://github.com/TheRobotStudio/SO-ARM100, Simulation/SO101), which is Apache-2.0.

Keep the package name `so_arm_description`: the URDF references its meshes as
`package://so_arm_description/meshes/...`.

## What it describes

One SO-101 arm, generated by onshape-to-robot:

- Links: `base`, `shoulder`, `upper_arm`, `lower_arm`, `wrist`, `gripper`, `jaw`.
- Revolute joints: `Rotation`, `Pitch`, `Elbow`, `Wrist_Pitch`, `Wrist_Roll`, `Jaw`.

The joint limits and inertias are the upstream CAD values. Nobody has checked them
against our arms.

## Not included

- The rig: where each arm's `base` sits, the fixed camera, and the camera mounted on an
  arm. Those transforms are calibration results and stay unset until measured.
- Arm prefixes. The rig has two arms, so run one `robot_state_publisher` per arm with
  its `frame_prefix` parameter (for example `left/`, `right/`) instead of editing link
  names.
- Joint drivers. The TF tree only moves when something publishes real `joint_states`.

Upstream's README mentions launch and RViz files that aren't in that repository. Its
`CMakeLists.txt` installs `meshes/`, `config/` and `urdf/`.
